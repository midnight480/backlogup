# BacklogUp

[English](README.md) | [日本語](README_ja.md)

> Fork 元: [common-creation/backlogup](https://github.com/common-creation/backlogup)

## これはなに

Backlog API を叩いて、指定したプロジェクトのデータをバックアップします。  
バックアップしたデータは簡易ビューアで閲覧できます。

## 主な機能・仕様 (Features & Specifications)

### 1. データバックアップ機能 (`npm run backup`)
- **完全ローカル保存**: 指定した Backlog プロジェクトのデータをローカル環境に JSON および実ファイルとして保存します。
- **バックアップ対象**:
  - **課題 (Issues)**: 課題本体、ステータス、優先度、カスタム属性、コメント、添付ファイル
  - **Wiki**: Wiki ページ本文、スター、添付ファイル、タグ
  - **ドキュメント (Documents)**: フォルダ/ファイルのツリー構造、ドキュメント本体、コメント（リプライ含む）、添付ファイル
  - **共有ファイル (Shared Files)**: ファイル共有領域をフォルダ階層ごと再帰的に走査し、ファイル一覧 (`shared-files/list.json`) を作成。実ファイルのダウンロードは件数が多くなりがちなため、`npm run backup` では行わず、別コマンド `npm run download:sharedfiles` で個別／一括に、中断後の再開もできる形で取得します（[詳細](#共有ファイルのダウンロード)）。元のフォルダ構造・ファイル名のままローカルに保存されます。
  - **プロジェクト設定**: 課題種別、カテゴリ、マイルストーン、メンバー一覧、**ライセンス情報**（プラン種別、ユーザー上限、ストレージ容量など）
  - **ユーザー情報**: ユーザーメタデータ、アイコン画像
- **差分更新対応**: 既に取得済みのデータが存在する場合、更新分のみを差分取得し、2回目以降のバックアップを高速化します。

### 2. ローカルアーカイブ・ビューア (SPA)
バックアップしたデータをオフラインで高速かつ直感的に閲覧できる React + Vite ベースのビューアです。

- **モダンなUIレイアウト**:
  - ヘッダーナビゲーションによる画面の広さを活かしたレイアウト構成（サイドバーレス）。
  - Tailwind CSS を活用したセマンティックなテーマカラー（緑色ベースの Primary カラー）と一貫したデザインシステム。
- **ダッシュボード**:
  - プロジェクトの基本情報、バックアップ進捗/統計、ライセンス情報などを一覧表示。
- **課題エクスプローラー**:
  - ページネーション対応の一覧テーブル表示（ステータスや優先度をバッジで視覚化）。
  - インデックスベースのローカルキーワード検索による課題の高速絞り込み。
- **Wiki / ドキュメント ビューア**:
  - 左ペインにパス構造から自動生成したフォルダツリーを表示。
  - **インクリメンタル検索窓**を搭載し、入力した文字列でページ名・ファイル名からリアルタイムにツリーをフィルタリング可能。
  - Wiki は Markdown 形式でのレンダリング、ドキュメントは Tiptap (ProseMirror) によるリッチテキスト表示をサポート。
  - 添付ファイルのダウンロード、コメントスレッドの階層表示にも対応。
- **ユーザー設定 (Settings モーダル)**:
  - **多言語対応 (i18n)**: 日本語 (JA) / 英語 (EN) の即時切り替え。
  - **テーマ設定**: ライトモード / ダークモードのトグル切り替え。
  - 各設定値はブラウザの `localStorage` に保存され、リロード後も維持されます。

## かんたん起動（非エンジニア向け・ほぼワンクリック）

コマンド操作に不慣れな方（事業部の情シス担当の方など）向けに、**ファイルをダブルクリックするだけ**で使える起動方法を用意しています。日本語のメニューが表示されるので、番号を選ぶだけでバックアップ・共有ファイルのダウンロード・ビューア起動ができます。

| OS | ダブルクリックするファイル |
|----|--------------------------|
| Windows | `start-windows.bat` |
| macOS | `start-mac.command` |

**使い方（共通）**

1. このリポジトリを ZIP でダウンロードして展開（または `git clone`）します。
2. お使いの OS に合わせて、上記のファイルをダブルクリックします。
   - 初回は Node.js のインストール確認と、必要パッケージの自動セットアップ（数分）が走ります。
   - Node.js が入っていない場合は案内に従って [公式サイト](https://nodejs.org/ja/download)から LTS 版を入れてください。
3. 初回は設定ファイル `.env` が自動で作られ、メモ帳／テキストエディットが開きます。
   次の3つを入力して保存してください（取得方法は下の表のとおり）。

   | 項目 | 入れる値 |
   |------|---------|
   | `BACKLOG_HOST` | Backlog のドメイン（例: `xxx.backlog.com`） |
   | `BACKLOG_API_KEY` | API キー（Backlog の 個人設定 → API から取得） |
   | `BACKLOG_PROJECT_KEY` | プロジェクトキー |

4. メニューが出たら、やりたいことの番号を入力して Enter:

   ```
   1) バックアップを実行する
   2) 共有ファイルをすべてダウンロードする
   3) ビューア（閲覧画面）を起動する
   4) データを全消去してからバックアップし直す
   5) 設定ファイル(.env)を開いて編集する
   0) 終了する
   ```

> 💡 macOS で初回に「開発元を確認できないため開けません」と出る場合は、`start-mac.command` を**右クリック → 開く**を選ぶと実行できます。

---

以降は、コマンドに慣れている方向けの手順です。

## バックアップの取り方

1. `sample.env` を `.env` にコピー
2. `.env` のコメント通りに必要事項を入力する
   - `BACKLOG_HOST` — Backlog のドメイン（例: `xxx.backlog.com`）
   - `BACKLOG_API_KEY` — API キー（個人設定 → API から取得）
   - `BACKLOG_PROJECT_KEY` — プロジェクトキー
3. `npm run backup` でバックアップを開始する

※ Backlog プロジェクトの規模によっては、バックアップに時間がかかります。

### ⚠️ プロジェクトキーを変更する場合（必須）

抽出されるデータはプロジェクトキーごとにフォルダが分かれておらず、常に同じ `dist/assets` ディレクトリに保存されます。
そのため、`.env` で **異なるプロジェクトキーに変更してバックアップを取得する際は、必ず事前にデータをリセットして総入れ替え** する必要があります。
（これを怠ると、複数のプロジェクトのデータが混ざってしまい、ビューアの表示が崩れる原因となります）

既存のバックアップデータを完全に削除し、新規バックアップを開始するには、`CLEAN_BACKUP=true` を付与して実行してください。

```bash
CLEAN_BACKUP=true npm run backup
```

## 共有ファイルのダウンロード

共有ファイルは件数が多くなりがちで、Web 画面の一括ダウンロードではタイムアウトすることがあります。本ツールでは「一覧の作成」と「実ファイルのダウンロード」を分離し、API で 1 ファイルずつ確実に取得します（API 実行回数は増えますが、レート制限は自動で 60 秒待機・リトライして回避します）。

1. `npm run backup` を実行すると、共有ファイルの**一覧のみ** `dist/assets/shared-files/list.json` に作成されます（この時点では実ファイルはダウンロードされません）。
2. その後、`npm run download:sharedfiles` で実ファイルを取得します。

```bash
# 一覧を表示する（ID・パス・サイズ）
npm run download:sharedfiles -- --list

# すべてダウンロードする（途中で中断しても、再実行で続きから取得）
npm run download:sharedfiles -- --all

# 指定した ID のファイルだけダウンロードする（個別）
npm run download:sharedfiles -- 123 456
npm run download:sharedfiles -- --id 123,456

# パスに指定文字列を含むファイルをまとめてダウンロードする（例: 特定フォルダ）
npm run download:sharedfiles -- --path 設計書
```

- 既にダウンロード済み（バイト数が一致する）ものは既定でスキップするため、大量のファイルでも安心して中断・再開できます。書き込みは一時ファイル経由でアトミックに行い、中断時に不完全なファイルが残らないようにしています。再取得したい場合は `--force` を付けてください。
- ダウンロードしたファイルは、Backlog 上の**元のフォルダ構造・ファイル名のまま** `dist/assets/shared-files/` 配下に保存されます。
- 1 件でもダウンロードに失敗した場合は終了コードを非 0 にします（自動化が不完全なアーカイブを成功とみなさないため）。

### ビューア画面から選択ダウンロード

`npm run dev` でビューアを起動すると、「共有ファイル」タブで一覧にチェックを入れて「選択をダウンロード」ボタンから取得できます。開発サーバーが `.env` の `BACKLOG_API_KEY` を用いて**サーバー側で** Backlog API を呼ぶため、API キーがブラウザに露出することはありません。取得したファイルは上記と同じ `dist/assets/shared-files/` に保存され、一覧にも即時反映されます（この機能は `npm run dev` 起動中のみ利用可能です）。

## 簡易ビューアのビルド

```bash
npm run build
```

`dist` ディレクトリに、バックアップデータも含めてアセット一式が保存されます。

### Antigravity での設定方法

Google Antigravity はファイルベースのルール自動読み込みに未対応のため、手動で Knowledge に登録する必要があります。

1. Antigravity を開く
2. 設定 → Knowledge を開く
3. `docs/coding-standards.md` の内容を Knowledge として追加する
